# Storycraft zh-TW

以繁體中文協助規劃、創作、續寫、編輯與測試長篇小說，也支援文字小說遊戲、視覺小說、互動式文字遊戲與分支敘事。

適合從萬字作品到千章級連載，透過分層故事記憶、事件帳本、角色狀態與連續性審計，維持長期創作的一致性與可追蹤性。

## 能力

- 規劃書名、前提、主線、分卷、弧段、章節與場景
- 建立故事聖經、角色卡、世界規則、關係網與伏筆表
- 續寫章節、場景與對話，並維持既有視角、語氣與人物邏輯
- 進行發展編輯、文字編輯、節奏診斷、讀者測試與連續性審計
- 支援愛情、推理、懸疑、恐怖、奇幻、科幻、武俠、歷史、政治、戰爭、生存、管理等類型
- 支援線性、連載、選項分支、探索揭露、指令模擬、關係數值、群像、多 POV、TRPG 風格與多周目模式
- 設計節點、選項、旗標、數值、物品、跳轉條件與多重結局
- 產出可移植的互動腳本，並可再轉換至 Ink、Twine、Ren’Py、Yarn Spinner、ChoiceScript 或 Inform 7
- 以台灣繁體中文創作，保護原創性，不直接仿寫特定作者或作品

## 長篇記憶

技能採用分層記憶，避免把整本作品一次塞入上下文：

| 層級 | 用途 |
| --- | --- |
| L0 | 使用者確認的硬性契約與不可變設定 |
| L1 | 角色、勢力、地點、物件、規則與名詞 |
| L2 | 分卷、弧段目標、轉折與角色變化 |
| L3 | 事件、因果、時間、狀態與角色知識 |
| L4 | 章節、場景摘要與未解問題 |
| L5 | 已核准的正文與原始證據 |

每章依「讀取 → 鎖定 → 創作 → 抽取 → 審計 → 提交 → 封存」處理。重要事件同時記錄故事時間與揭露時間，避免時間線、伏筆和角色知識邊界漂移。

## 互動敘事

互動作品使用「節點—選項—條件—結果」模型。每個選項都應具有可理解的意圖、即時回饋、延遲後果與明確可逆性，並檢查：

- 節點與結局是否可達
- 是否存在死路、孤立節點或無限循環
- 旗標與數值是否有穩定命名、寫入點與讀取點
- 選項是否造成真正的劇情、關係、資訊或資源差異
- 存檔、讀檔、跳過文字與多周目是否破壞狀態

## 安裝

將此倉庫作為一個技能套件放入你的技能目錄，保留以下結構：

```text
storycraft-zh-tw/
├── SKILL.md
└── agents/
    └── openai.yaml
```

技能名稱為 `storycraft-zh-tw`。完成安裝後，可直接提出創作需求；也可以明確指定：

```text
使用 $storycraft-zh-tw 規劃一部十二卷的長篇懸疑小說。
```

## 使用範例

```text
使用 $storycraft-zh-tw 建立故事聖經，並只規劃第一卷的八章。

使用 $storycraft-zh-tw 依照目前故事狀態續寫下一章，先列出章節契約再寫正文。

使用 $storycraft-zh-tw 檢查前十章的時間線、角色知識與伏筆回收狀態。

使用 $storycraft-zh-tw 設計一個具有三條主要路線和四個結局的視覺小說節點規格。
```

## 設計原則

- 先辨識工作模式，再載入最少且最相關的上下文
- 故事聖經是導航；已核准正文、事件來源與使用者確認優先
- 診斷、規劃、創作、修訂與審計分開處理
- 未確認的推測標示為未知，不將其寫成既定事實
- 每次完成工作都保留決策、未解問題與下一個停止點
